# M-Control v1.4.6 Hotfix

本次处理两条 GT77HX 灯效反馈（含补充诊断）和一条 GP68HX 麦克风快捷键反馈。四份 GT77 诊断逐份对比，并核验全部附件；正式基线仍为 v1.4.0。

## 修复

- **GT77 CHERRY 灯位**：Legacy 纯色、关闭、Disco、Aurora、GoldSplash 和 ReactiveKey 按 GT77 的实际键位生成完整 assignment，补齐此前遗漏的 CHERRY。
- **灯效设备恢复**：补齐 GT77 已知灯效接口；确认设备被禁用时先启用再重启，接口返回后重新应用此前已成功保存的灯效。GT77 后置接口仍缺失时明确报告未完成。
- **灯效诊断**：诊断包增加 `lighting_device_state.txt`，记录灯控接口的系统状态、驱动和错误码，便于继续定位后置灯条/龙盾接口缺失。
- **F5 麦克风快捷键**：平台已经切换时避免再次反转；补写明确目标并读回 Windows 实际状态，减少单击无效及 OSD 与系统不一致。

## 升级与复测

GT77 用户升级后，在键盘灯效页重新应用原效果，检查普通键和 CHERRY 是否一起变化。龙盾或尾灯仍不亮时，使用一次 **“恢复灯效设备”**，等待结果后再生成诊断包；请把新的 ZIP 追加到原反馈，保留结果和时间。

四份旧诊断都只有键盘接口，后置 ALC 未被枚举，缺少最初正常时的系统设备状态。**本版修复已确认的生成和恢复缺陷；原机 ALC 最初消失的原因、龙盾和尾灯实际恢复效果仍待实机确认。** 请勿仅凭“键盘可控”判定所有灯区已经恢复。

GP68HX 用户用单次 F5/Fn+F5 对照 Windows 输入设备的实际静音状态和 M-Control OSD，确认开启、静音都能稳定往返；仍有差异时追加新版诊断与视频。

## 验证

- 6 个 app JS 语法、150 个 Node 测试文件、686 项 xUnit 测试通过，0 跳过；Release 构建 0 警告/0 错误。
- 新增 63 项 CHERRY、设备恢复及音频状态回归，其中 12 项 CHERRY 漏键用例先失败再通过。
- 原协议黄金字节、Chakra516 程序哈希和质量预算保持原有要求；PRISM 按现有算法和机型 descriptor 生成，没有加入抓包帧重放。
- 自动回归未代替用户反馈设备的硬件写入实测。
